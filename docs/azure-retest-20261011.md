# Azure 원스톱 재시험과 캐시 재사용

2026-10-11, 일본 서부 B4as_v2(4 vCPU·16GB), CPU Ollama `gemma4:e2b`·`bge-m3`에서 측정했다.
질문부터 Tavily 수집, 주장 추출·번역, 문서 간 유사도, 로컬 신뢰도 함수, 보고서까지 실행했다.
시험 결과는 사람 승인 전 초안이다.

## 재사용 조건

수집기가 같은 기사에 새 문서 ID를 부여하면서 기존 검증 캐시가 빗나가는 문제를 수정했다.
질문·원문 문단·언어·모델 digest·프롬프트·옵션이 같은 검증 결과를 재사용하고,
문서·문단·주장 ID를 현재 수집 건에 연결한다. 원래 모델 응답과 검증 이력은 보존한다.
보고서는 전체 근거, 출처, 가중치, 문서 유사도, 반환 점수까지 일치할 때만 재사용한다.
사람의 승인 상태는 재사용하지 않는다. 실패·미검증 모델 응답도 캐시에 넣지 않는다.

Tavily 검색·수집은 새로 실행된다. 새 기사, 변경된 snippet, 다른 질문은 새 분석이 필요하다.
캐시 적중은 기존 모델 판단의 정확성을 더 높이는 검증이 아니다.

## 실측 범위

- 대만해협 질문의 수정 전 재실행: 10개 기사, 대표 주장 10개, 상세 후보 44개,
  문서 쌍 45개. 검색부터 보고서까지 1,194초(19분 54초).
- 같은 10개 문서의 ID를 모두 바꾼 캐시 재생성: 1.707초. 새 LLM 호출 0회,
  임베딩 호출 0회. 새 검색·수집은 포함하지 않은 분석·신뢰도·보고서 실측이다.
- 인도·파키스탄: 15개 기사, 대표 주장 15개, 상세 후보 57개, 문서 쌍 105개.
  입력·인용 오류를 수정하고 저장된 단계부터 재개해 보고서까지 완료했다.
  실패한 시도까지 합친 누적 처리 시간은 2,253.127초(약 37분 33초)이며,
  마지막 보고서 재개는 449초(7분 29초)였다. 수동 코드 수정 대기 시간은 제외했다.
  수정 후 처음부터 끝까지 무중단으로 다시 실행한 측정값은 아니다.
- 같은 15개 문서의 ID를 모두 바꾼 캐시 재생성: **0.244초**, 새 LLM·임베딩 호출 **0회**.
  검증 JSON은 ID 이외의 값이 동일하고, 보고서 입력 해시는 현재 ID 기준으로 다시 연결됐다.
- 추가 대만해협 검색에는 새 기사 8개가 포함돼 기존 10개 자료의 캐시 재시험과
  동일 조건이 아니었다. 이 추가 실행은 수집 후 취소했으며 완료 사례로 세지 않는다.

새 자료를 처리하는 전체 시나리오의 3분 완료는 달성하지 못했다. CPU 사양·기사 길이·
번역 재시도·보고서 근거 대조에 따라 달라지며, RAM 용량만으로 처리 시간을 보장할 수 없다.

## 실제 입력에서 수정한 방어 처리

1. 힌디어·우르두어의 `।`, `॥`, `۔`, `؟`를 문장 경계로 처리한다.
   인도·파키스탄 최초 수집은 우르두어 snippet이 최대 9,373자로 늘어나 입력 제한으로
   중단됐다. 기존 본문과 문서 15개를 보존하고 해당 언어의 snippet 7개만 다시 구성했다.
2. 분리된 웹주소·푸터 조각을 번역할 주장 후보에서 제외한다.
   실제 도서 홍보 글의 도메인 조각이 한국어 번역 검사를 실패시킨 사례를 회귀 테스트했다.
3. 보고서의 공통·상충 후보에 잘못된 인용 ID가 있으면 한 번 재요청한다.
   그래도 중복·미등록 ID가 남은 비교 문장만 제외 기록에 보존한다. 근거 쌍을 꾸며서
   채우지 않으며 전체 기사·주장·점수는 유지한다. 핵심 판단의 잘못된 인용은 계속 거부한다.

## 품질 판정

문서 수, 기사당 대표 주장, 다른 모든 문서에 대한 `sim`, 대칭성, 원문 인용,
반환 점수와 입력 해시, 미승인 초안 상태를 자동 검사한다.
이 검사는 문장의 사실 여부나 번역 의미의 정확성을 보증하지 않는다.

실제 출력에는 부정 표현의 범위, 기관명·지명 번역 오류, 메뉴·사진 설명 잔존,
질문과 관련도가 낮은 기사 및 비교 후보가 발견됐다. 인도·파키스탄 수집에는 크리켓,
도서 홍보, 러시아·우크라이나 기사도 포함됐으며 설정된 양국 정부 도메인의 원문은
확보하지 못했다. 최근 30일 검색만으로 역사적 분쟁 원인을 충분히 설명했다고 볼 수 없다.
따라서 내용 품질을 합격 처리하거나 보고서를 승인하지 않았다.

인도·파키스탄 보고서의 상충 후보에도 동일 대상·시점에서 모순이라고 볼 수 없는
문장 쌍이 남았다. 이 항목은 LLM 제안으로만 표시되고 사람 선택 전 확정되지 않는다.
모든 15개 주장의 반환 라벨은 `판단 보류`다. 신뢰도 수치만으로 사실 확인의 강도를
판단하는 보고서 표현도 사람 검토가 필요하다.

PDF에는 CJK 글꼴을 포함하지만 우르두어·힌디어 글리프를 지원하지 않는다.
실제 인도·파키스탄 PDF에서 원문이 네모로 표시되는 현상을 확인했다.
이번 공유 결과 묶음은 원문을 보존하는 JSON과 MD를 제공하며 PDF는 제외한다.
다국어 PDF 글꼴과 RTL·복합문자 조형 지원은 남은 작업이다.

## 재현·결과 보관

[배포 안내의 벤치마크 명령](../deploy/azure/README.md)을 사용한다. 질문은 `--question`,
언어는 `--languages`, 공식 출처 점검 국가는 `--coverage-countries`로 지정한다.
`--run-id`는 기존 실행의 결과를 내려받고 새 검색을 시작하지 않는다.

로컬 결과는 `data/deployment/azure-20261011-retest/` 아래에 보관한다.
`taiwan-repeat/`에는 검색어·수집·분석·검증 입력·신뢰도 JSON과 보고서가 있다.
인도·파키스탄은 최초 실패, 재개, 보고서 복구 결과를 별도 폴더로 보존한다.
재개 시 화면 경과 시간은 현재 시도부터 계산하므로 전체 처리 시간은 최종
`scenario-run.json`의 `stage_seconds` 합계로 확인한다. 수동 수정 대기 시간은 이 합계에서 제외된다.
전체 원문·결과 JSON·접속 정보는 Git에 올리지 않는다.

Python 구문 컴파일 통과. `frame/`에는 기존 Ruff 스타일 경고 91개가 남아 있다.
