# Tavily 원문 → 주장·번역·문서 유사도

스토리보드의 실제 수집 완료 결과에서 **주장·유사도 분석**을 실행한다. 원문 수집은 그대로 유지되며 분석 실패가 수집 성공 기록을 덮어쓰지 않는다. 분석 결과를 화면에서 확인하고 JSON으로 내려받을 수 있다.

API: `POST /api/collections/{수집ID}/analysis` (빈 본문). 완료된 수집 파일을 읽어 로컬 Ollama로 분석하고 `docs`, `claims`, `warnings`를 반환한다. `GET /api/collections/{수집ID}/analysis/download`로 다운로드한다. 새 수집 작업이 진행 중이면 분석할 수 없다.

`GET /api/collections/{수집ID}/analysis/status`는 분석 요청이 실행되는 동안에도 진행 상태를 반환한다. 화면에서 1초 간격으로 현재 단계의 완료율·항목 수·경과 시간·LLM 응답 수신 글자 수를 표시한다. 추출 단계는 검증 완료 본문 묶음 수, 비교 단계는 확인 완료 문서 쌍 수가 분모다. `stage_completed`, `stage_total`, `stage_percent`가 현재 단계이고 `completed`, `total`, `percent`는 전체 항목 기준이다. 퍼센트는 소수점 한 자리로 표시하며 남은 시간의 비율은 아니다. 단계가 바뀌면 새 단계 완료율은 0부터 시작한다. 전체 완료율은 저장 성공 이후에만 100%다. 준비 중에는 비율 없이 움직이는 막대를 표시한다. 응답 수신량은 작업 활동을 알리는 값이며 완료율로 환산하지 않는다.

```json
{
  "docs": [
    {"id": "d0", "country": "JP", "weight": 0.5, "score": 0.81, "sim": {"d1": 0.93}},
    {"id": "d1", "country": "US", "weight": 0.8, "score": 0.72, "sim": {"d0": 0.93}}
  ],
  "claims": [
    {"claim_id": "d0-c1", "document_id": "d0", "tier": 2, "event_date": null,
     "paragraph_id": "d0-p1", "original_quote": "40分間の予定です。",
     "translated_quote": "40분간 예정되어 있다.", "expression": "예정"}
  ],
  "warnings": []
}
```

위 수치는 가상 예시다. `id`는 수집기의 `doc_id`, `weight`는 `credibility_weight`, `score`는 Tavily 검색 관련도를 그대로 전달한다. LLM이 가중치·국가·티어를 결정하지 않는다. `claim_id`는 문서 ID와 다른 개별 주장 ID다.

`sim`은 두 문서에서 추출한 질문 관련 주장들의 의미 유사도(0~1)이며 검색 관련도·사실 일치율·신뢰도가 아니다. 최대 8개의 문서 쌍을 한 호출에서 비교하고 각 쌍의 값을 양쪽에 동일하게 넣는다. 누락·중복·요청하지 않은 쌍이 있으면 실패로 처리한다. 자기 자신은 제외한다. 주장 부족·비교 입력 한도 초과이면 null과 경고를 반환한다. 국가와 문서 언어는 별개의 수집 메타데이터다.

문단을 최대 6,000자 묶음으로 분석한다. 더 긴 단일 문단은 최대 인용 길이와 같은 1,600자 겹침을 두고 분할하며 문단 ID는 보존한다. 각 묶음에서 근거가 명확한 질문 관련 핵심 주장 최대 12개를 추출한다. 동일한 인용·번역·표현은 중복 제거한다. 전체 원문에 존재하지만 추출되지 않은 내용까지 유사도가 평가하는 것은 아니다. 비교 입력은 18,000자 이하이며 임의로 일부 주장을 잘라 비교하지 않는다.

수집기의 문단 목록이 전체 `article_text`를 포함하지 않으면 전체 본문용 추가 문단을 분석한다. 본문에 포함된 앞부분을 별도로 재분석하지 않는다. 기존 문단 하나에만 존재하는 인용은 기존 ID에 연결하고, 나머지는 추가 문단 ID를 유지한다. 추가 문단 ID·원문은 `analysis_paragraphs`에 보존하며 이 문단을 인용하는 주장도 검증할 수 있다. 따라서 수집기에서 앞부분만 만든 문단 목록 때문에 기사 뒷부분이 조용히 누락되지 않는다.

인용은 실제 전달 문단의 부분 문자열인지 코드로 검사한다. 인용을 통과한 모든 주장은 별도 LLM 호출에서 원문 문맥과 한국어 번역의 주체·시제·부정·예정·수치·범위·조건·발언 주체·사건 날짜 보존 여부를 검토한다. 불일치 또는 판단 불가인 주장만 원문·원래 추출 대상·오류 코드를 붙여 최대 2회 재추출한다. 주장 번호는 유지하고 재추출 결과도 인용·의미를 다시 검사한다. 정상 주장을 다시 추출하거나 실패 주장을 삭제하지 않는다. 응답의 주장 번호 누락·중복·추가도 실패다. 2회 이후에도 확인되지 않으면 해당 근거를 빼고 점수를 만드는 대신 분석을 중단한다. 재추출 이력은 `warnings`, 검증 실패 사유·원시 응답은 trace에 보존한다. 검증 중에는 현재 본문 묶음의 진행률을 완료로 올리지 않는다.

의미 검증은 동일 로컬 모델의 별도 판단이며 의미 정확성을 보장하는 확률·최종 신뢰도가 아니다. 사람의 최종 검토가 필요하다. 원문을 수정하거나 유사 문자열로 맞추지 않는다. 사건 날짜가 명시되지 않으면 null이다. 출력 미완료·스키마 위반은 실패로 처리한다.

분석은 CPU에서 순차 호출하며 컨텍스트 16,384·temperature 0·입력 배치 256을 사용한다. 출력 최대치는 주장 추출·재추출 4,096토큰, 의미 검증·유사도 비교 1,024토큰이다. `OLLAMA_TIMEOUT`은 개별 호출의 벽시계 제한이며 전체 분석이 하나의 300초 제한을 공유하지 않는다. 정상 본문 묶음도 추출 후 의미 검증 호출이 추가된다. 검증·재추출 입력은 전체 원문 문맥을 유지하고 주장 목록을 18,000자 이하로 묶는다. 단일 주장도 한도를 넘으면 실패한다. 10문서의 45쌍 비교는 입력 크기가 허용하면 6회 호출로 처리한다. 각 문서의 주장은 비교 묶음 안에서 한 번만 전달한다.

원문 인용·번역 의미 또는 비교 쌍 검증까지 통과한 응답은 `data/analysis-cache/`에 저장한다. 잘못된 초기 추출 응답은 저장하지 않는다. 성공한 재추출·의미 검증 요청은 재사용할 수 있다. 동일 모델 digest·프롬프트·명세·설정·입력 요청은 재사용하며, 질문이나 본문이 바뀐 추출 요청은 다시 분석한다. 모델 digest가 없으면 캐시를 사용하지 않는다. 캐시 적중 여부는 trace의 `cache_hit`에서 확인할 수 있다. 캐시 저장 실패는 분석 결과를 실패로 바꾸지 않는다.

결과의 `timings`는 추출·의미 검증·재추출·유사도 단계별 실측 초, 실제 LLM 호출 수·캐시 적중 수를 반환하고 화면에도 표시한다. `analysis_seconds`는 분석 함수 전체, `total_seconds`는 모델 확인·해제까지 포함한 시간이다. trace의 각 호출에는 `phase`, `elapsed_seconds`가 남으며 실패·시간 초과도 측정한다. 캐시 안의 과거 Ollama `total_duration`을 이번 처리 시간으로 집계하지 않는다. API는 실패 시에도 `{수집ID}-timings.json`을 저장한다. 별도 표본 측정 결과는 [성능 측정 기록](source-analysis-performance.md)을 참고한다.

결과는 `data/source-analyses/{수집ID}.json`, 요청·원시 응답은 `{수집ID}-trace.json`에 저장한다. 화이트리스트·최종 검증·신뢰도 공식은 이 단계에서 수정하거나 실행하지 않는다.

검색어 생성도 단계별 진행률을 반환한다. 공통 의미 분석 1단계와 한국어 외 선택 언어별 번역 1단계씩을 계산하며, 언어·날짜·용어 검사 및 계획 조립까지 통과한 응답만 `data/search-cache/`에 저장한다. 모델 digest·요청·프롬프트·설정이 같은 캐시 응답도 의미·번역 검사를 다시 통과해야 사용한다. Tavily는 최대 2개 언어를 동시에 검색·본문 수집하며, 각 작업자의 클라이언트·필터 상태를 분리하고 입력 언어 순서대로 중복을 제거한다. 실패·취소 시 후속 요청을 중단한다. 이미 전송된 요청의 응답은 기다릴 수 있다. 수집 결과의 `timings.query_seconds`, `collection_seconds`, `total_seconds`는 모델 해제 및 수집 처리를 포함한 실측 시간이다.
